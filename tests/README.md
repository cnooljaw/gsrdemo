# 跨进程验收与故障演练

实际接线时建立独立集成测试 Go module，并由 scripts 中统一脚本自动枚举。日常包测试留在对应节点/common，不复制 GSR 框架测试。

首轮验收必须跑五进程及至少三客户端：分别登录 → 同组入座 → 满员开局 → 地鼠出现/命中 → 结束 → 待结算 → 积分到账 → 查询余额及账本。同组共享目标、分别计分；竞争同一实例只奖励首个合法命中者，重复命中、过期实例与重复结算不得重复加分。至少再建一组验证目标、广播及分数隔离。全组（含零分及断线成员）同事务记账，不允许部分到账被报告为完成。

进程及 MySQL 演练显式启用，有总超时；等待明确事件/readiness，不依赖随机 sleep。强杀与回收只针对测试自己启动的进程。已保存结果在重启后补结算；未保存结果不假报到账。三人斗地主另验私人手牌隔离、非法操作不改变状态和三人同事务结算。

当前没有多进程或数据库测试，不代表这些行为已验证。
